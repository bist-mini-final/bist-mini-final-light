# 온보딩 준비 점검

기준: 2026-10-16. 모든 새 PC에서 설치를 보장한다는 뜻은 아닙니다.

| 영역 | 확인 범위 |
| --- | --- |
| 실행 | run.py 한 번으로 API·정적 UI·네 종류 로컬 워커 실행 |
| DB | Windows PostgreSQL 16.15 + pgvector 0.8.6, 별도 5433 클러스터 |
| 스키마 | 새 스키마의 멱등 초기화·기업 비교 범위 제약 DB 통합 검사 |
| GPU 모델 | 현재 PC의 CUDA llama.cpp b11429 + Qwen3.5 4B + BGE-M3에서 텍스트·이미지·임베딩·도구 호출 |

## 이번 변경 검사

- 실제 PostgreSQL 통합 검사를 포함한 백엔드 408개 통과.
- 전체 Python 타입 검사 오류 0, ruff 통과.
- 설정 화면 테스트 9개 통과, 프론트 빌드 성공.
- 문서 상대 링크와 폴더 가이드의 진입 파일 존재 확인.
- 설치 PowerShell 문법과 기존 키 보존·설정 실패 시 원본 유지 회귀 검사 통과.

## 환경별 조건

- 완전히 빈 새 PC에서 수 GB 다운로드를 포함한 설치 전체를 반복한 것은 아닙니다. 실행 검증과 설치 코드·배포 파일 점검을 구분합니다.
- 기본 Qwen3-VL과 현재 PC에서 재사용한 Qwen3.5는 다른 모델입니다. 정확도·메모리·속도가 같다고 보장하지 않습니다.
- macOS/Linux 수동 설치는 문서화했으며 이 Windows PC에서 직접 실행하지 않았습니다.
- OpenAI 계정별 접근 권한·잔액은 별도입니다. 점검 도구는 키 존재만 검사합니다.
- 사내 프록시·방화벽이 GitHub·Hugging Face·conda-forge를 막으면 담당자의 네트워크 설정이 필요합니다.
- 4B 모델 답변은 셀과 대조해야 합니다. 셀 기반 샘플 BI가 RAG 정확도 검증을 대신하지 않습니다.

## 신규 학생의 완료 기준

1. `check_environment.py` 실행 전 검사 통과.
2. run.py 실행 후 `check_environment.py --online` 통과.
3. 첫 샘플 적재 후 챗봇 수치·셀 근거 대조.
4. 전체 샘플 BI와 두 기업 비교 확인.
5. 종료·재실행 방법과 개인 데이터 저장 위치 이해.

명령 앞에는 `uv run python scripts/`를 붙입니다. 자세한 순서는 [ONBOARDING.md](ONBOARDING.md)를 참고하세요.
